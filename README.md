# Стартовый шаблон сервиса на Python с машинным обучением

Каркас для кейса «Предскажи сбои выгрузок данных»: FastAPI, PostgreSQL, scikit-learn, тесты,
запуск одной командой. Скачайте шаблон, создайте из него свой репозиторий на GitHub и пишите
решение здесь.

## Как платформа запускает решение

Так же, как вы можете запустить его у себя, только без Docker:

- язык платформа узнаёт по файлу `requirements.txt` в корне репозитория;
- сервис стартует командой `uvicorn app.main:app` и слушает порт 8000;
- базу PostgreSQL поднимает сама платформа, её адрес — в переменной `DATABASE_URL`;
- для своих файлов (например, SQLite) есть папка из переменной `DATA_DIR`;
- проверка начинается, когда сервис ответит на `GET /health`, — на это есть 60 секунд;
- сети на проверке нет, а библиотеки — только те, что в `requirements.txt` этого шаблона:
  свои зависимости платформа не устанавливает.

Поэтому не переименовывайте `app/main.py` и объект `app` в нём и не меняйте версии в
`requirements.txt`.

## Запуск у себя

Одной командой, нужен Docker:

    docker compose up --build

Сервис будет на http://localhost:8000, проверка: http://localhost:8000/health.

Без Docker — нужны Python 3.12 и PostgreSQL:

    python -m venv .venv && . .venv/bin/activate
    pip install -r requirements.txt
    export DATABASE_URL=postgresql://app:app@localhost:5432/app
    uvicorn app.main:app --reload --port 8000

## Тесты

    pytest

## Что здесь лежит

| файл | зачем |
|---|---|
| `app/main.py` | приложение FastAPI и `/health` |
| `app/db.py` | подключение к базе и создание схемы |
| `train.py` | обучение модели — пишете вы; модель кладёте в `model/` |
| `model/` | обученная модель обычным файлом: платформа её не обучает |
| `tests/` | тесты; добавляйте свои |
| `compose.yaml`, `Dockerfile` | запуск одной командой у себя; платформа их не запускает и не проверяет |
